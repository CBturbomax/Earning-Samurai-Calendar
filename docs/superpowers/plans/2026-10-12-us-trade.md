# US Trade Implementation Plan

Goal: Add usable US exports/imports with five years of real monthly data and sourced company interpretation.
Architecture: Standalone static us-trade/ UI; stdlib Census XLSX collector; daily Actions refresh; navigation from existing pages.
Spec: User requests US export/import equivalents and meaningful related companies.
Constraints: Census nominal USD, seasonally adjusted End-use classification explicitly labeled. Do not infer company trade shares. Missing != zero. Preserve cache on failure. No API credentials needed.

1. Collector: parse official XLSX DATE/ENDUSE/DESCRIPTION/VALUE, retain 72 months (60 visible plus YoY), validate duplicate/malformed dates/values, complete selected series and regression against prior snapshot. Test before implementation.
2. UI: exports/imports tabs, search, 12/36/60 months, USD amount/YoY, latest initial scroll, month-header descending/ascending sorting, sticky category/company column. Sourced company notes distinguish positive/negative conditional interpretation and unknown shares.
3. Integration: root build.py and Japan nav links, daily workflow with failed-refresh status and existing-cache preservation; tests in CI. Test collector, JS metrics and root build; review then deploy.

Review focus: overlapping category totals; wrong units; missing/zero denominators; stale/backward releases; company manufacturing geography differs from headquarters.
Decision: Use publicly downloadable Census seasonally adjusted End-use data because HS API now requires a key. No country breakdown or precise HS-only claim in this first version.

Verification ledger: 7 collector tests and JS metrics pass. Full repository unittest: 10 tests pass; existing daily/monthly table JS tests pass.
