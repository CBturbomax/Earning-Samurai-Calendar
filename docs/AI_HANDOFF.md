고친다(한 회사만 손으로 고치지 말 것 — 같은 병의 다른 회사들이 그대로 남는다).

### 빈칸 점검 장치 (2026-11-01 만듦)
- `build.py` 의 `audit_gaps()` 가 빌드마다 `data/audit_gaps.json` 에 다섯 가지를 시총 큰 순으로 적고 빌드 로그에
  「빈칸 점검(전체 · 시총 1조↑): …」 한 줄과 큰 회사 다섯씩을 찍는다.
  - `gap` 1Q18 이후 실적 차트 가운데가 빈 회사 · `stale` 발표했는데(캘린더 날짜 2~60일 전) 그 분기 숫자가 없는 회사 ·
    `seg` 실적은 최신인데 사업부 마지막 분기가 뒤처진 회사 · `opi` 최근 12분기 중 영업이익이 빈 회사 ·
    `short` 시총 1조↑인데 실적이 2020년 뒤에야 시작하는 회사(옛 이력을 못 잡았을 수 있음).
- 그 목록을 **수집기가 먼저 다시 받는다**: `scrape_fin.py`(미국)·`scrape_fin_intl.py`(일본·홍콩)의 `queue` 가
  stale·gap·opi 회사(시총 1천억↑)를 앞줄에, `scrape_seg_pr.py`(numbers.yml)가 사업부 뒤처진 미국 회사의
  **8-K 보도자료 사업부 표를 바로 읽고**, 실시간 서버 `audit_fill()`(두 시간마다 + replay `auditfill`)이 보도자료를 다시 읽는다.
- 첫 측정(11/01): gap 1,193(1조↑ 381) · stale 497(157) · seg 832(465) · opi 73(37) · short 1,064. **이 숫자를 0 으로
  만드는 것이 일이다.** 줄어드는지 매번 재고, 안 줄면 원인을 찾는다. (stale 에는 반기·연간만 내는 회사의 오탐이 섞여 있다 —
  그런 오탐은 점검 규칙을 고쳐 없앨 것.)

### 지금까지 찾은 원인(같은 병이 또 나오면 여기부터)
1. **발표 당일 사업부가 비는 것**(구글·MS·메타 3Q26): 사업부는 10-Q 가 나와야(벌크·edgar) 들어온다 → `scrape_seg_pr.py`
   (보도자료 표를 전년 값 대조로 읽음, AI 아님). 구글·메타·코카콜라는 읽혔고 MS·아마존·테슬라·마스터카드는 표 이름이 달라
   못 읽었다 — **다음 할 일: 이 회사들의 보도자료 표 생김새를 probe 로 떠서 규칙을 넓힐 것.** 서버의 AI 판독
   (`seg_ai_try`)은 사이트 부문 이름이 한글로 옮겨져 있어 영어 이름과 짝이 안 맞는 일이 있다(원문 이름으로 맞출 것).
2. **SEC 태그를 갈아탄 회사의 구멍**(3M 3Q21~1Q23 등 929곳): 옛 태그 몇 분기가 재작성돼 어긋나면 통째로 버리던 것 →
   `scrape_fin.py` 의 `mostly()`, FIN_VER 9 로 전 종목 다시 받는 중(backfill_us.yml).
3. **홍콩 20기간 한계** → 동방재부(`scrape_fin_hk_em.py`, 숫자가 전부 위안이라 환율로 되돌림). 수집 진행 중.
4. **일본 사업부**: 결산단신에 부문 태그가 없는 회사(도쿄일렉트론·이토추 등), 2023년 전엔 태그 자체가 없음, 옛 EDINET 이력
   단위 어긋남 → 1분기 = 상반기 누계 − 2분기 단독, 4분기 값 짝짓기, 한 칸 튐(`seg_unannual`)까지 했다. **남은 것: IR PDF 를 읽는 길.**
5. **연간·누계가 분기 칸에**(에스티로더) → `seg_unannual`.
6. 반기 회사에 분기 이름(홍콩·외국 기업) → `seg_align` 이 실적 차트 이름(1H/2H)을 쓰게 했다.

### 왜 회원님 MCP 는 되고 어닝사무라이는 안 되나 (다음 AI 가 기억할 것)
- InvestingWiki MCP 는 **원문 공시(TDnet·SEC·DART)를 직접, 10년치를 자기 DB 에 쌓아 두고** 물을 때 바로 꺼낸다. 어닝사무라이는
  무료 집계 사이트(stockanalysis 20기간·며칠 늦음, SEC 벌크 두 분기 늦음 등)에 기대는 곳이 아직 많고, 소스마다 이름·단위·
  기간이 달라 이어 붙이는 자리에서 구멍이 난다.
- 방향: **원문 공시를 1차 소스로**(미국 8-K 보도자료·10-Q XBRL, 일본 결산단신 XBRL·설명자료, 홍콩 HKEX PDF/동방재부), 받은 원문은
  버리지 말고 쌓아 두고(raw), 집계 사이트는 메우기용으로만. 발표 당일엔 서버가 원문에서 바로 읽고, 빌드의 빈칸 점검이 놓친 것을
  다시 돌린다. "소스가 늦다"는 핑계가 되지 않는다 — 원문은 발표 그 시각에 있다.

## 1. 회원님과 말하는 법 (어기면 바로 지적받는다)

- **한국어로, 짧고 쉽게.** 했던 말 반복 금지. 결론 먼저. 영어로 답하면 "한글로 해야지"가 온다.
- **과정이 아니라 결과를 보고한다.** "서버 재시작" 같은 내부 사정은 말하지 않는다.
- **"데이터가 없다"고 말하지 않는다.** 없으면 다른 소스를 찾아 메운다. 정말 원본이 없으면 그 이유를 짧게.
- **디자인(화면 모양) 변경은 먼저 시안 이미지를 보여주고 허락받는다.** 실제 데이터로 그린 스크린샷을
  `SendUserFile` 등으로 보내고 물어본 뒤 적용한다. 허락 없이 바꿨다가 되돌린 적이 있다(가이던스 차트 11/01).
- **물어만 본 것은 만들지 않는다.** "가능해?"에는 가능 여부·무게·방법을 답하고 신호를 기다린다.
  "해봐/ㄱㄱ/오케이"면 바로 한다.
- 속도가 중요하다("빠릿빠릿"). 긴 일은 백그라운드로 돌리고 중간 결과를 짧게 알린다.
- 숫자를 지어내지 않는다. 틀린 숫자보다 빈칸이 낫다. 다만 빈칸은 끝까지 메우려 노력한다.
- 텔레그램으로 내부 점검 보고(예: 가이던스 점검)를 보내지 않는다 — 회원님이 하지 말라고 했다.
- 토큰·비밀번호는 채팅에 받지 않는다. Railway Variables / GitHub Secrets 에만.

## 2. 회원님 취향(화면·데이터)

- 실적 이력은 **1Q18 부터**(2017년 값은 1Q18 전년비 계산용으로만). 빈 분기는 빈칸으로 두고 앞을 자르지 않는다.
- 차트는 어닝사무라이 고유 형식: 어두운 배경, 파란 막대/선(#5B9BD5), 금색 최신(#FFCB05), 주황 이익률(#ED7D31),
  분기 이름은 세워 쓰고 해가 바뀌는 칸막이는 **이름 줄에만**, 숫자는 굵고 크게(`.vn` 클래스 — 테두리 있는 숫자).
  한 눈에 많이 보이는 걸 좋아하지만 **글씨가 작은 건 싫어한다**.
- 성장률 축: -20% 밑은 안 봐도 됨. 튀는 값은 자르지 말고 위·아래 띠에 눌러 담아 높낮이를 남긴다(`yoyMap`).
- 일본 금액 표기: bil JPY 한 자리 3.2, 두 자리 13.2, 세 자리부터 소수점 없이 103.
- 오름 빨강 · 내림 파랑(한국식). 시가총액은 상자로 강조.
- 가이던스는 숫자보다 **상향/하향/유지** 상태가 중요. 일본 가이던스는 반드시 채운다.
- 텔레그램 실적 알림: 숫자는 차트, 글은 '왜'만. 🏢 비즈니스 줄은 시총 위에, **구체적인 제품명**으로("메모리 테스트 핸들러").
- 빼는 업종: 은행·리츠·부동산·도시가스·지역전력·임대·일본 철도/지하철·택배물류·해운·ETF/ETN.
- 가이던스 대폭 상향(이익 +30%·매출 +15%)은 관심 범위 밖이어도 🚀 로 보낸다.
- 일본 월매출 카드: "N월 월 매출", "🔥 매출 YoY : +x%". 기존점 YoY +10% 이상이면 알림.

## 3. 작업 요령 (이 환경에서 실제로 쓴 방법)

- **올리기**: `tools/ai/push.sh "메시지" 파일…` — 따로 둔 클론에서 커밋·푸시(작업 폴더를 안 건드림, 잠금 있음).
  수집 봇이 main 에 3~5분마다 커밋하므로 `git push` 가 자주 밀린다 — 이 스크립트가 다시 받아 재시도한다.
  **고치기 전에 작업 폴더를 `git checkout --detach origin/main` 으로 최신에 맞추고 시작**할 것(옛 판 위에 고쳐 올리면
  남이 고친 것을 덮는다). 올린 뒤에는 `git checkout -- . && git clean -fd data/` 로 작업 폴더를 비운다.
- **서버(Railway) 배포**: Railway 는 `railway` 가지를 본다. main 에 올린 뒤
  `git push -f origin origin/main:refs/heads/railway`. 배포 결과는 railway 가지 SHA 의 커밋 status(success)로 본다.
- **밖으로 못 나가는 환경**(이 세션은 프록시가 야후·SEC·JPX·Railway 를 막았다): `.github/workflows/probe.yml` 에
  단계를 넣고 `tools/ai/probe.sh` 로 돌려 결과를 `probe-out` 가지의 `probe.txt` 로 읽는다. probe 단계는 쓰고 나면 정리.
- **서버 명령**: main 의 `replay.txt` 첫 줄에 새 id(f40, f41…), 다음 줄부터 명령(jphist, jphistrev, irhist, guideaudit,
  segfill N, jpday …). 서버가 1분 안에 읽고 스레드로 돈다. 진단 `/health` `/api/log` `/api/stats` `/api/audit`.
- **빌드 확인**: 로컬에서 `python build.py`(2~3분) → `python -m http.server` → Playwright(Chromium 내장)로
  `openModal(key, date)`·`finChart(D.fin[k])`·`segChart(D.seg[k])` 를 불러 스크린샷. 실시간 서버 값은 로컬에서
  안 오므로 전역 객체(`PX`, `LQ`)에 가짜 값을 넣어 시험.
- 큰 작업 뒤에는 `CLAUDE.md` 해당 자리에 '왜 그렇게 했는가'를 남긴다(실측 숫자와 실패 사례 포함 — 이 저장소의 문화다).

## AI 빈칸 메우기 — 여러 구독 나눠 쓰기 (11/02)
- `ai_seg.claude()` 는 `AI_ENGINE=codex` 면 `codex exec`(ChatGPT 구독)로 묻는다. 아니면 `claude -p`.
- ai_fill.yml 네 갈래: 0=CLAUDE_CODE_OAUTH_TOKEN, 1=CLAUDE_CODE_OAUTH_TOKEN_2, 2·3=CODEX_AUTH_JSON(~/.codex/auth.json 내용). 빈 열쇠는 남은 것으로 대신.
- 한도에 한 번 걸리면 그 갈래는 곧장 멈춘다(AIFILL_RETRY=1). 갈래당 2줄. 종량제 API 키로는 안 돈다.
- 아직 `if: false`(꺼짐). 회원님이 열쇠를 넣고 각 계정의 추가 사용량(크레딧)을 끈 걸 확인한 뒤에만 켠다.
