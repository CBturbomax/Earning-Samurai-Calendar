# 일본 결산발표 캘린더 (JP Earnings Calendar)

일본 상장사 결산발표(決算発表) 일정을 주(週) 단위로 보는 단일 HTML 페이지.
레이아웃은 [EarningsHub](https://earningshub.com/earnings-calendar) 주간 캘린더를,
디자인은 [taiwan-it-revenue](https://cbturbomax.github.io/taiwan-it-revenue/)를 따랐다.

## 구성

| 파일 | 역할 |
|---|---|
| `scrape.py` | 닛케이 결산발표 스케줄 수집 → `data/earnings.json` |
| `companies.py` | 주목종목 사전 (코드 → 한글명·영문명·테마) |
| `translit.py` | 일본 회사명 → 한글 표기 변환기 |
| `build.py` | `data/earnings.json` → `index.html` |
| `index.html` | 산출물. 외부 의존 없는 단일 파일 (폰트 CDN만 사용) |

## 쓰는 법

```bash
python scrape.py 2026-07-20 2026-09-30
```

```bash
python build.py
```

`index.html`을 그대로 GitHub Pages에 올리면 끝. 서버가 필요 없다.

## 데이터 출처

日本経済新聞「決算発表スケジュール」(QUICK 제공)
<https://www.nikkei.com/markets/kigyo/money-schedule/kessan/>

날짜 범위 조회가 안 되고 하루씩(`SearchDate1=2026年08`, `SearchDate2=12`)만
50건 페이징으로 나온다. 그래서 날짜 × 페이지 두 겹으로 긁는다.

### 레이트리밋 주의

연속 30~40 요청쯤에서 **본문 없는 껍데기 페이지**를 돌려주기 시작한다.
이걸 "0건"으로 삼키면 발표가 몰린 날이 조용히 빈 날이 되므로,
`fetch_valid()`가 건수 표시(`N件目を表示`)나 `0件` 문구 중 하나를 반드시
확인하고, 없으면 15/45/120/300초로 물러섰다 재시도한다.

- 하루 받을 때마다 `data/earnings.json`에 **증분 저장**한다.
- 이미 받은 날은 다시 안 긁는다. 중간에 죽어도 **같은 명령을 다시 돌리면
  못 받은 날만** 이어서 받는다.
- 한 번 막히면 꽤 오래 안 풀린다. 실패가 이어지면 몇 분 쉬었다 재실행.

## 한글 표기

원본은 전부 일본어라 그대로 두면 훑어보기가 안 된다. 화면에 보이는 글자는
모두 한글(또는 로마자)로 옮겼다.

- **업종·시장·결산기·휴일** — 닫힌 집합이라 `build.py`에서 전량 대역.
  `電気機器`→전기기기, `東証`→도쿄, `3月期`→3월 결산, `山の日`→산의 날.
- **회사명** — `translit.py`. 세 등급으로 나뉜다.

| 등급 | 방식 | 비중 |
|---|---|---|
| 2 | `companies.py` 수기 한글명, 또는 원래 로마자 사명 | 13% |
| 1 | 단어 사전으로 전부 커버 | 13% |
| 0 | 기계 변환 (가타카나 음운 + 한자 한국음) | 75% |

변환기가 하는 일:

1. 전각 영숫자를 반각으로. `ｒｏｂｏｔ ｈｏｍｅ` → `robot home`
2. 알파벳을 가나로 늘어놓은 사명을 로마자로 환원.
   `ジーエヌアイ`→`GNI`, `アイ・アールジャパン`→`IR재팬`.
   둘 이상 잇달아야 인정한다. `アイスコ`의 `アイ`까지 `I`로 바꾸면 곤란하다.
3. 지명·기업명·업종어 사전(`WORDS`)을 긴 것부터 매칭.
4. 남은 구간은 가타카나 음운표(요음·촉음·발음·장음 처리)와
   한자 626자 한국음표로 옮긴다. 낱말 첫머리엔 두음법칙 적용.

### 한계

한자 지명·인명은 **훈독**이라 한국 한자음으로 읽으면 틀린다.
`小田原`은 오다와라인데 '소전원'이 되는 식이다. 자주 나오는 것은 `WORDS`에
직접 넣어 막았지만(`東急`→도큐, `丸八` 같은 것은 여전히 '환팔'로 나온다)
전부는 못 잡는다. 그래서

- 기계 변환분(등급 0)은 **점선**을 그어 구분하고, 마우스를 올리면 원문이 뜬다.
- 표에 **원문 열**을 따로 두었고, 캘린더에는 **원문(일본어) 토글**이 있다.
- 검색은 한글·원문·영문·코드 어느 쪽으로도 걸린다.

이름이 틀렸으면 `companies.py`(주목종목) 또는 `translit.py`의 `WORDS`에
한 줄 넣고 `build.py`를 다시 돌리면 된다.

## 페이지 기능

- **관심종목 알림** — ☆ 를 눌러 담으면 `localStorage`에 저장. D-day로 표시.
- **.ics 내보내기** — 관심종목/이번 주 일정을 캘린더 파일로. 하루 전
  알림(`VALARM`)이 들어 있어 구글·아웃룩 캘린더에 넣으면 실제 알림이 온다.
  정적 페이지라 서버 푸시가 없어 이 방식을 택했다.
- **주간 캘린더** — 요일별 칸. 주목종목을 ★로 위에 올리고 나머지는 접어둔다.
  주말은 발표가 잡힌 주에만 칸이 열린다. 휴장일은 사유를 적는다.
- **주목종목 발표일** — 테마별(반도체 장비·소재·부품 …) 다음 발표일.
- **전체 종목 표** — 검색·업종·시장·분기 필터, 정렬.

## 한계

- 회사명 한글 표기는 위의 「한계」를 참고. 원문을 늘 함께 볼 수 있게 해두었다.
- 발표 **시각**은 원본에 없다. 일본은 대부분 장 마감 후 15시 전후 발표.
  EarningsHub의 Before Open / After Close 구분에 대응하는 값이 없어
  분기(1Q/2Q/3Q/본결산)로 갈랐다.
- 실적 **수치**(매출·EPS·컨센서스)는 이 소스에 없다. 일정만 다룬다.
- 발표일은 예정일이고 회사 사정으로 바뀐다. 갱신하려면 다시 긁어야 한다.
- 시가총액이 없어 "주목종목"은 `companies.py`의 수기 목록에 의존한다.
  종목을 추가하려면 그 파일에 한 줄 넣고 `build.py`를 다시 돌리면 된다.
